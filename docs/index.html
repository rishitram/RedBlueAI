AI security testing · OWASP A03: Injection

RedBlueAI

Two AI agents play attacker and defender. The red-team agent finds and exploits SQL injection in a Flask/SQLite app, and the blue-team agent rewrites the code with parameterized queries. It also runs on every pull request through GitHub Actions.

View on GitHub Try the demo

🚧 Work in Progress: RedBlueAI is under active development, with plans to expand beyond SQL injection to detect other security vulnerabilities, including improper exception handling, while improving agent reliability and automated testing.

How it works

Both agents run a tool-calling loop on Google Gemini through an OpenAI-compatible API. They can only use four tools, all of them sandboxed.

Red-team agent

Lists and reads the app's Python source, spots SQL built from user input, then sends real payloads to the local app to confirm that each finding can be exploited.

Blue-team agent

Takes the findings and writes app_fixed.py, replacing string concatenation with ? placeholders. The original file is left untouched so you can compare the two.

CI scanner

A GitHub Actions workflow runs ci_scan.py on each pull request and posts the findings back as a PR comment.

The fix

    
What the blue-team agent changes. With placeholders, the database treats input strictly as data, never as SQL.

    

      

        
Before: string concatenation


# target_app/app.py
query = (
    "SELECT id, username, role FROM users "
    "WHERE username = '" + username + "' "
    "AND password = '" + password + "'"
)
cur.execute(query)

      

      

        
After: parameterized query


# target_app/app_fixed.py
query = (
    "SELECT id, username, role FROM users "
    "WHERE username = ? AND password = ?"
)
cur.execute(query, (username, password))

      

    

  






  

    
Built-in guardrails

    
The agents are only given these tools, and every one of them enforces its own limits.

    

      
list_files / read_file
Paths are resolved inside the scan directory and the repo root. Any .. or absolute path that escapes either one is refused.

      
write_file
Can only write inside the scan directory the agent was launched with.

      
send_request
Hard-locked to http://127.0.0.1:5000. The agent can't reach any other host.

    

  






  

    
Run it yourself

    
The target app is intentionally vulnerable, so the full system only runs locally.

    
    
      
  1. Clone and installgit clone https://github.com/rishitram/RedBlueAI.git → pip install -r requirements.txt
    2. 
      
  2. Add your LLM keySet LLM_API_KEY, LLM_BASE_URL and LLM_MODEL in a .env file
    3. 
      
  3. Start the target apppython target_app/app.py (binds to localhost only)
    4. 
      
  4. Attack, then defendpython agent/attack_agent.py, then python agent/defense_agent.py
    5. 
    

    
Security notice: target_app/app.py is broken by design, in the same spirit as OWASP Juice Shop. Never deploy it to a public server.
